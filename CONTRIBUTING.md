# Участие в разработке

Словофон / Slovofon — приложение для аудиокниг на Android, Android TV и Windows.
Помочь проекту можно исправлением ошибки, проверкой на устройстве, переводом или
улучшением документации. Для сообщения о проблеме код писать не обязательно:
начните с [раздела поддержки](SUPPORT.md).

## Перед изменениями

1. Проверьте [открытые issues](https://github.com/Dushnyj/Slovofon/issues), чтобы
   не дублировать уже обсуждаемую задачу.
2. Для крупной функции сначала опишите пользовательский сценарий и затронутые
   платформы в [предложении](https://github.com/Dushnyj/Slovofon/issues/new?template=feature_request.yml).
3. Прочитайте [правила проекта](AGENTS.md) и профильный документ:

   | Область | Документ |
   | --- | --- |
   | Функции и платформы | [Техническое ТЗ](docs/SLOVOFON_TECHNICAL_SPEC_RU.md) |
   | Слои и потоки данных | [Архитектура](docs/ARCHITECTURE.md) |
   | Источники и сетевые границы | [Источники](docs/SOURCES.md) |
   | Тема, цвета и состояния | [Дизайн-система](docs/THEMING.md) |
   | Сборка и инструменты | [Сборка и релизы](docs/BUILD_RELEASE.md) |
   | Секреты и пользовательские данные | [Безопасность](docs/SECURITY.md) |

ТЗ описывает и реализованные, и запланированные возможности. Текущие ограничения
и границы проверок приведены в [отчёте о качестве](docs/CROSS_PLATFORM_QUALITY.md).

## Локальное окружение

Основной сценарий разработки использует Flutter/Dart и PowerShell. Версию Flutter,
с которой собирается релиз, можно посмотреть в [.github/workflows/release.yml](.github/workflows/release.yml).
Не меняйте зависимости или инструменты только ради приведения к более новой версии.

```powershell
git clone https://github.com/Dushnyj/Slovofon.git
cd Slovofon
./tools/slovofon.ps1 check
./tools/slovofon.ps1 bootstrap
```

Для отправки PR используйте свою ветку и fork репозитория. Системные зависимости
для Android и Windows описаны в [руководстве по сборке](docs/BUILD_RELEASE.md).
Bootstrap не заменяет установку отсутствующего SDK или подтверждение его лицензии.

## Как подготовить изменение

- Один PR — одна логическая задача. Отделяйте исправление поведения от массового
  форматирования и обновления зависимостей.
- UI обращается к контроллерам и сервисам, а не напрямую к сети или файлам.
  Логика источника остаётся в connector; плеер и загрузки не получают отдельные
  несовместимые реализации для каждой платформы.
- Используйте общие компоненты и semantic colors. Проверяйте светлую и тёмную
  темы, фокус/hover и текст 75–200%; для TV — навигацию без мыши.
- Пользовательские строки храните в локализации, а не в widgets. Изменения
  форматов данных должны сохранять существующие настройки, книги и прогресс.
- Для исправленного бага добавьте регрессионный тест. Сетевые тесты делайте
  воспроизводимыми с локальными fixtures, без токенов и закрытых данных источников.
- Обновите профильную документацию и `CHANGELOG.md`, если меняется поведение.
  Версию, signing config и релизные артефакты в обычном PR не меняйте.

Сообщения коммитов: `type(scope): краткое описание`, например
`fix(player): preserve position after paused restore`.

## Проверки перед PR

Проверки и Debug-сборки выполняются локально. GitHub Actions используется только
для согласованных релизов; push и PR не запускают отдельный CI. Релизный workflow
повторяет необходимые проверки перед публикацией, но не заменяет локальное QA.

Из корня проекта:

```powershell
./tools/slovofon.ps1 format
./tools/slovofon.ps1 analyze
./tools/slovofon.ps1 test
```

При изменении платформенного кода или UI соберите соответствующий Debug-таргет:

```powershell
./tools/slovofon.ps1 build -Target android -Configuration debug
./tools/slovofon.ps1 build -Target windows -Configuration debug
```

Для общего UI проверьте обе сборки и затронутые экраны. Укажите в PR устройство,
размер окна/экрана, тему и масштабы. Сборка и widget-тесты не заменяют проверку
звука, фоновой работы и пульта на устройстве. Недоступную проверку пометьте
«не проверено» с причиной, а не как успешную.

- [Чеклист телефона и Android TV](docs/MANUAL_DEVICE_QA_RU.md)
- [TV-контракты и тестирование](docs/ANDROID_TV_TESTING.md)

## Данные, безопасность и лицензия

Не прикладывайте к коммитам и PR ключи подписи, `key.properties`, токены, cookies,
сетевые headers, полные media URL, пользовательские базы или скачанные книги.
В диагностике оставляйте только необходимый обезличенный фрагмент;
[правила безопасности](docs/SECURITY.md) действуют и для изображений/вложений.

Не обходите media allowlist и не сбрасывайте пользовательские данные ради теста.
Новые зависимости и сторонние ассеты должны иметь понятную лицензию и запись в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
Проект распространяется под [Apache License 2.0](LICENSE); сохраняйте лицензионные
уведомления. Публикация релиза, создание тегов и изменение подписания — отдельные
действия владельца, не часть обычной проверки PR.
